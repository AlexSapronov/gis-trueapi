# XML УПД 5.03 по сканам отгрузки

Редакция: 16.11.2026. [Навигация](../README.md).

### Заполнение XML УПД по сканам отгрузки

В карточке завершённой отгрузки с актуальной успешной проверкой откройте
**«Заполнить XML УПД кодами маркировки и ГТД»**:

1. Загрузите неподписанный титул продавца УПД **5.03**, до 10 МБ.
2. Для каждой строки выберите PN из отсканированной отгрузки либо явно
   «Без маркировки». GTIN в XML из БП не нужен. PN определяется по
   `ДопСведТов/@АртикулТов`, иначе по `НаимТов` без описания в скобках в конце.
   Полное наименование остаётся на экране; исходное наименование не меняется.
3. При необходимости включите сохранение связей PN. Успешно подтверждённые
   связи хранятся в SQLite отдельно для каждого ИНН продавца и предлагаются
   при следующих загрузках; их можно изменить новым выбором и сохранением.
4. По необходимости включите «Получать и подставлять ГТД из ЧЗ» (по умолчанию
   выключено) и нажмите «Подготовить XML». Без флажка исходные ГТД сохраняются
   без запроса к ЧЗ. С флажком backend запрашивает
   `cises/short/list` пакетами до 1000 КИ и связывает ответы по КИ,
   независимо от порядка ответа. Если КИ найден, но ГТД не указана, приложение
   показывает план перестройки строк и целые упаковки вместо общей ошибки.
   Отсутствующий КИ, ошибка API и отсутствие номера ГТД различаются.
5. Выберите вывод из оборота для всего УПД: «Без вывода — передать КМ покупателю»
   либо причину `1` (собственные нужды), `2` (безвозмездная передача),
   `3` (производственные цели) или `4` (государственный / муниципальный контракт).
   Для причин 1–3 последующая продажа товара не предполагается. Выбранная причина
   записывается как `ТекстИнф Идентиф="СвВыбытияМАРК" Значен="…"` в
   `СвСчФакт/ИнфПолФХЖ1`. Исходное значение подставляется при загрузке;
   выбор «Без вывода» удаляет признак. Остальные дополнительные сведения сохраняются.
   Для причины 4 заполните `СвСчФакт/ДопСвФХЖ1/@ИдГосКон` в 1С до загрузки XML.
   Нестандартные или повторяющиеся исходные признаки можно сохранить отдельным
   вариантом либо заменить выбранной причиной.
6. Проверьте таблицу КМ/ГТД и скачайте XML. Подпись и отправка выполняются
   после загрузки файла в используемый модуль ЭДО.

Одинаковые PN могут встречаться в нескольких строках XML из-за разбиения по
ГТД в 1С. С включённым получением ГТД такие строки сначала объединяются в
группу одного сопоставленного PN с одинаковыми ценой, НДС и прочими
коммерческими реквизитами. Проверяется суммарное количество группы, затем
строки создаются заново по фактическим ГТД/GTIN из ЧЗ. Например, исходные
80 + 20 шт. могут стать 60 + 40 шт., если такое распределение
подтверждено целыми КМ и их ГТД. При одной ГТД группа станет одной строкой.
Каждый КМ используется ровно один раз. Количество берётся из
проверенного `quantityInPack`, упаковки не делятся между строками. Все КМ
отгрузки должны быть распределены. Поддерживаются товарные строки в штуках
(ОКЕИ 796). Если у выбранного PN несколько GTIN, они также разделяются.

Для каждого сочетания ГТД и GTIN создаётся отдельная строка: количество и КИ
только этой группы; суммы без НДС и НДС распределяются пропорционально
количеству с округлением до копейки, остаток распределяется так, чтобы итоги
всех объединённых исходных строк сохранялись точно. Цена за единицу и итоги документа
сохраняются; строки перенумеровываются. В XML записывается КИ без криптохвоста,
GS/FNC1 и AI30. Создаётся новый ИдФайл с признаком маркировки, имя скачиваемого
файла совпадает с ИдФайл.

Если ЧЗ не указал ГТД хотя бы для части КМ, XML автоматически не выдаётся.
Вместо этого видны исходные строки/ГТД, группы по известным ГТД и КМ без ГТД,
количества и состав целых упаковок. Отдельно предлагаются ближайшие границы
строк по целым КМ, с сохранением максимально возможного числа исходных строк.
Когда КМ меньше, чем строк, предлагается объединение. Этот вариант подтверждает
только количества: принадлежность КМ исходным ГТД пользователь уточняет отдельно.
После исправления XML в 1С можно загрузить его снова с выключенным флажком и
сохранить подтверждённые исходные ГТД. Без флажка приложение также показывает
такой план, если исходные границы проходят внутри КМ, без запросов ГТД в ЧЗ.
Предыдущий подготовленный файл при появлении плана становится недоступен;
в истории фиксируется необходимость проверки. Связи PN сохраняются при
успешной подготовке готового XML.

Входной и выходной XML проходят офлайн-проверку по вложенной XSD 5.03
(источник и ограничения — [описание XSD](../schemas/README.md)). ИНН продавца и, если задан,
покупателя сверяются с отгрузкой. Страна происхождения сохраняется из XML:
**поиск ГТД не подтверждает страну**. Разбиение строк с числовым акцизом,
прослеживаемостью и дополнительными налоговыми суммами блокируется.
Исходные XML, результаты и связи сохраняются в складской SQLite; действия
записываются в историю. Изменение версии/реквизитов отгрузки делает старую
подготовку недоступной — загрузите XML повторно.

При обновлении установите зависимости (`pip install -r requirements-lock.txt`)
и перезапустите службу; таблицы создаются автоматически. Обратную загрузку и
сохранение изменённого исходящего XML нужно проверить в вашей версии 1С/ЭДО.

Проверки: `python -m pytest -q`; дополнительно
`python tests/browser_upd.py` при установленном Playwright Chromium.
