# Проверка ГТД в сводном Excel

Редакция: 16.11.2026. [Навигация](../README.md).

### ГТД в сводной выгрузке Excel

В общей админке есть раздел **«ГТД в Excel»**. Он принимает `.xlsx` до 10 МБ
с таблицами `Number`, `FromINN`, `GoodName`, `Amount`, `Declaration`.
Поддерживается исходная выгрузка с пустым столбцом A и заголовками со столбца B.
Строки группируются по ИНН отправителя, ИНН получателя и номеру документа БП.
Номер БП задаёт границы одной отгрузки; номер и дата складской накладной могут
отличаться. `ToINN` должен быть заполнен для сопоставления.

1. При необходимости раскройте **«Справочник GoodID → GTIN»**, скачайте шаблон
   и загрузите две колонки `GoodID`, `GTIN`. Связи сохраняются в SQLite.
   Повторная загрузка обновляет перечисленные GoodID, остальные связи остаются.
   Один GoodID не может указывать на два разных GTIN в одном файле.
   GTIN проверяется по контрольной цифре; 13 цифр дополняются ведущим нулём.
2. Загрузите сводную выгрузку. При наличии связи `GoodId` используется GTIN,
   даже если наименование ERP отличается от PN склада. Без связи применяется
   PN из `GoodName` без описания в скобках в конце и сохранённые связи PN из УПД.
3. Программа ищет единственную завершённую отгрузку (включая архив) с теми же
   ИНН отправителя и получателя и полным составом `GTIN → количество`.
   Повторные строки одного GTIN внутри номера БП суммируются. Сравниваются все
   товары документа; одна отгрузка не собирается из нескольких складских накладных
   и не используется для двух разных номеров БП. Немаркируемые позиции участвуют
   в сравнении по PN/количеству, но их ГТД не заменяются по КМ.
   При нескольких одинаковых составах результат признаётся неоднозначным.
   Проверяются актуальность складской сверки и неизменность выбранной отгрузки. ГТД запрашивается по
   конкретным КИ сканов, **не по одному GTIN вообще**: у него могут быть разные ГТД.
4. Проверка идёт в фоне, прогресс виден на странице; последний результат
   восстанавливается в текущем браузере после перезагрузки страницы.
5. Скачайте результат. `Declaration` заменяется на подтверждённое значение ЧЗ.
   Изменённые строки выделены жёлтым; в интерфейсе есть фильтр изменений.
   Исходные листы, порядок столбцов и прочие поля сохраняются, добавляется лист
   **«Проверка ГТД»** с исходными номерами БП, номерами/датами сопоставленных складских накладных, результатами и пояснениями.

Если строке соответствуют несколько ГТД или исходная граница проходит внутри
КМ, простые совместимые строки пересобираются по целым КМ с сохранением
суммарного количества и `GoodsItemTotal`, включая исходную точность суммы.
Пересобранные строки также выделяются. Формулы, таблицы, связанные диапазоны,
объекты и дополнительные суммы не пересчитываются автоматически: такие
группы остаются без изменений с пояснением.

Ненайденные/неоднозначные отгрузки и товары, расхождения количества, возвраты,
отсутствующая ГТД или ошибка API сохраняют исходные строки. Их статус —
«Не подтверждена». При отсутствии ГТД у части КМ не меняется вся группа товара.
Суффикс номера товара после регистрационного номера ДТ не переносится из старой
декларации в новую: записывается только то, что вернул API.

Все маршруты `/api/admin/warehouse/gtd-excel` и `gtd-catalog` требуют
административного доступа. Файлы/результаты хранятся в SQLite. Изменение
связанной отгрузки или справочника после проверки требует новой обработки
перед скачиванием. После перезапуска прерванная проверка помечается неуспешной.
Новые таблицы создаются автоматически, новых зависимостей нет.
