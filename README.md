# gis-trueapi — складская работа с маркировкой

Web-приложение для проверки КМ через True API ГИС МТ, складской приёмки и отгрузки, подготовки файлов КМ и XML УПД. Интерфейс работает на ПК и Android-ТСД с аппаратным DataMatrix-сканером.

Документация сверена с исходниками ветки `main` на 16.11.2026.

## Возможности

- Одиночная и пакетная проверка КМ, статус, владелец, количество в упаковке и баланс по GTIN.
- Приёмка по точному списку ожидаемых полных КМ; отгрузка с проверкой статуса и количества через ЧЗ.
- Общие задания и сканы на нескольких устройствах, список или карточки накладных, обращения склада и ответы администратора, архив и корзина.
- Импорт стандартного Excel, готовой таблицы DataMatrix и массовой выгрузки накладных с ИНН; справочник GoodID → GTIN.
- Подготовка неподписанного XML УПД 5.03 по завершённой отгрузке: сопоставление PN, добавление КИ, получение ГТД, разбиение по целым упаковкам и выбор признака выбытия.
- Проверка ГТД одного КМ, сводного Excel и массового списка КМ, получение количества в упаковке.
- Восстановление недостающих PDF этикеток из имеющихся полных КМ без эмиссии.
- Несколько организаций с раздельными токенами, кабинет создания заданий для отдела продаж, передача приёмок из `marking-bm`.

`quantityInPack` — число единиц товара внутри КМ; число сканов означает число КМ. Завершённая приёмка подтверждает локальную сверку, завершённая отгрузка — проверенный состав. Само приложение не подписывает и не отправляет УПД в ЭДО.

## Быстрый запуск

Python 3.11/3.12; команды выполняются из корня клонированного репозитория:

```bash
git clone https://github.com/AlexSapronov/gis-trueapi.git
cd gis-trueapi
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
cp .env.example .env
.venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000`. По умолчанию используется `GIS_MODE=mock`. Для административного входа задайте в `.env` собственный случайный `ADMIN_KEY` и перезапустите приложение. Для live настройте фактические организации, `GIS_MODE=live` и авторизацию каждой организации по инструкции эксплуатации. Примеры ИНН в `.env.example` вымышлены.

## Рабочие страницы

| Адрес | Назначение |
|---|---|
| `/` | Одиночная/пакетная сверка и баланс |
| `/warehouse?kind=receipt` | Приёмка для склада |
| `/warehouse?kind=shipment` | Отгрузка для склада |
| `/admin` | Вход администратора, документы, токены, настройки и инструменты |
| `/sales-shipments` | Кабинет отдела продаж при настроенных персональных ссылках |
| `/api/status` | Состояние приложения и идентификатор сборки |

Администратор входит по `ADMIN_KEY`; складские страницы индивидуальных учётных записей не имеют. Для удалённой работы нужны HTTPS и сетевое ограничение доступа. Кабинет отдела продаж защищается отдельными ключами ссылок. Ключи и токены создаются при установке и не берутся из примеров.

## Данные и обновления

SQLite `WAREHOUSE_DB` хранит документы, полные КМ, сканы, проверки, XML, результаты Excel и настройки. `TOKENS_FILE` хранит токены отдельно; `.env` содержит секреты. Сохраняйте все три части защищённо. Для работающей SQLite используйте Backup API; порядок восстановления описан в руководствах. Не размещайте базу на сетевом диске.

Перед обновлением сделайте согласованную резервную копию, обновите выбранный проверенный коммит, установите `requirements-lock.txt`, перезапустите службу и проверьте `/api/status`. Схема SQLite инициализируется при запуске. При совместном обновлении связи приёмок сначала обновляется `gis-trueapi`, затем `marking-bm`.

## Проверки

```bash
python -m pytest -q
node --test tests/*.test.cjs
node --check static/app.js
```

Для браузерных сценариев установите Playwright и Chromium; доступны `tests/browser_warehouse.py`, `tests/browser_upd.py`, `tests/browser_km_report.py`. Локальные проверки с имитацией API не заменяют проверку полномочий, реального сканера и обработки документов в используемом контуре ЧЗ/ЭДО.
